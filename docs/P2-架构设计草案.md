# P2 架构设计：解析层 + 前端 + 部署（草案）

> 前置结论（P1）：原后端 `parse.yuantujun.com/miniParse` 依赖微信登录签名，网页版不可复用
> → 复刻版解析层 = 自研平台适配器 + CORS 代理

---

## 1. 解析层架构

### 1.1 统一接口
```js
// src/adapters/index.js
parse(shareText) → Promise<ParseResult>

ParseResult = {
  platform: 'douyin'|'kuaishou'|'weishi'|'weibo'|'taobao'|'unknown',
  type: 'video'|'images'|'live',
  title: string,
  cover: string|null,
  mediaUrl: string|null,      // 无水印视频直链（video 类）
  images: string[],           // 图集（images 类）
  desc: string,
}
```

### 1.2 适配器列表（按 P1 平台清单）
| 平台 | 域名特征 | 解析策略 |
|---|---|---|
| 抖音 | douyin.com, v.douyin.com | 短链展开 → 提取 video_id → 官方 oEmbed/公开接口 → 无水印直链 |
| 快手 | kuaishou.com, kuaishouapp.com | 短链展开 → 提取 photoId → 公开接口 |
| 微视 | h5.weishi.qq.com | 提取 vid → 公开接口 |
| 微博 | weibo.com, weibo.cn | 提取微博 id → 公开接口 |
| 淘宝 | tb.cn, taobao.com | 提取商品/视频 ID（该平台反爬严，可能降级为仅提取链接） |

> 各平台公开接口会变动/反爬，适配器必须隔离在独立文件，失效时单独更新（P1 风险表已列）。

### 1.3 CORS 代理层
- 主代理：`https://corsproxy.io/?url=`（或 cors-anywhere 公共实例）
- 回退链：corsproxy.io → allorigins → 用户自建 Cloudflare Worker（预留配置位）
- 策略：同一请求失败自动切换下一代理；本地 localStorage 缓存解析结果（带 TTL）
- 所有请求走 https；不存储任何用户数据到服务器

### 1.4 分享文案解析（核心前端逻辑）
1. 粘贴文本 → 正则匹配平台域名 → 提取 URL
2. 短链展开（follow 重定向，经 CORS 代理）
3. 按平台提取 ID → 调该平台解析逻辑
4. 图集/视频分流 → 组装 ParseResult

## 2. 前端架构（GitHub Pages 纯静态）

### 2.1 方案 A：零依赖原生（首选，环境无可用 npm）
- 单页应用：`index.html` + `app.js`（ES Modules）+ `style.css`（手写移动端优先）
- 无构建步骤、无 node_modules → Pages 部署即上传即用
- 页面视图（hash 路由或纯 JS 切换）：首页 / 解析结果 / 历史 / 常见问题 / 使用教程
- 状态：localStorage（历史、设置）

### 2.2 方案 B：Vite + Vue（若 pnpm 可用）
- 体验更好但依赖工具链；仅当 corepack/pnpm 能安装成功时采用

### 2.3 UI 设计（用户授权自由发挥，风格参考 P1 结论）
- 主色 `#005bc1` 蓝 + 白底 `#f0f4f9`
- tabBar：首页 / 历史记录
- 首页：大输入框（粘贴即自动识别）、平台徽标、解析按钮、最近解析
- 结果页：视频播放器（封面 poster）/ 图集画廊 / 保存 / 复制链接 / 分享
- 历史页：记录列表（平台图标 + 标题 + 时间），点击重新查看
- FAQ/教程：静态内容页
- 移动端优先，桌面端居中卡片

## 3. 功能复刻范围（P3 交付）

| 功能 | 状态 |
|---|---|
| 粘贴链接自动解析（5 平台） | ✅ 核心 |
| 视频/图集预览 | ✅ |
| 下载（视频 Blob、图集打包/逐张） | ✅（浏览器能力内） |
| 复制链接 / 分享（Web Share API） | ✅ |
| 历史记录（localStorage） | ✅ |
| 直播解析（liveurl 类） | ⚠️ 视平台支持 |
| FAQ / 教程页 | ✅ |
| AI 修复去水印（inpainting） | ❌ 网页端不现实，预留接口位 |
| 会员/豆/广告 | ❌ 移除（免费版） |
| 客服引流 | 替换为邮箱/公众号占位 |

## 4. 部署（P5 预演）

- 仓库结构：`docs/`（分析）、`src/` 或根目录静态文件（站点）、`tools/`（逆向工具）
- GitHub Actions：推送到 main → `actions/upload-pages-artifact` + `deploy-pages` 发布
- 若零依赖：构建步骤为空，直接发布静态文件
- 自定义域名（可选）、`robots.txt`、移动端 meta
